# Folio 10/10 Product Experience Standard

Date: 2026-06-24

This standard governs the user-facing Folio V2 experience. It supersedes earlier UX prompts as a single product-quality bar.

## Definition

A 10/10 Folio experience means a tired, worried, non-technical person can open the app, understand what Folio is for, choose a path that matches their real money concern, add or try data, review what Folio found, inspect why a number appears, and leave feeling clearer rather than judged.

Folio must feel obvious, calm, useful quickly, emotionally safe, serious, personalisable, trustworthy, human and inspectable. It must not feel like a spreadsheet, calculator, admin console, architecture diagram, generic fintech dashboard or chatbot wrapper.

## Principles

1. One obvious next step.
2. Useful in under 60 seconds.
3. Start with the user's mental model.
4. Review before anything counts.
5. Gentle reveal for stressful information.
6. Manual entry must feel like building a picture, not filling a form.
7. Import must be honest, never magical.
8. Debt, bills, income and survival pressure are first-class.
9. Every number can explain itself.
10. The route must answer a real question.
11. Melo guides the next action, not the whole product.
12. Advanced control exists but is not the default.
13. No screen should feel like an architecture diagram.
14. No screen should make the user feel stupid.
15. If the user hesitates, the screen failed.

## Required First Value Moments

- Payday: show what has to last until the next income and the tightest point before then.
- Debt: show debt payments beside income and bills without advice or shame.
- Bills: show must-pay items before flexible spending.
- Bank activity: show rows found to check and state that nothing has been added yet.
- Unsure: ask for one starting number, then build the smallest useful picture.

## Product Rules

- Start with a lens, not a dashboard.
- Keep Start, Review, Today and More as the main first-run areas.
- Hide Timeline, Calendar, Plans, Data and privacy, Melo help and internal test mode until needed.
- Make manual entry conversational: question, why it matters, estimate path, skip path, immediate consequence.
- Make Review powerful: what Folio found, what it might be, what happens if added, and what the user can do.
- Make import reality explicit: CSV/text can be read when supported; PDFs, screenshots and unsupported files are review-only.
- Make unsupported files useful by offering manual paths from the file.
- Make the route sober and inspectable: today, available money, next income, bills, debt payments, protected buffer, lowest point, review items and changed items.
- Make "show why" available for major numbers, warnings and route points.
- Keep Melo bounded: interpret, explain and suggest next steps; never directly change records.

## Completion Bar

A screen passes only if a cold user can continue without explanation, a worried user does not feel judged, a control user can inspect the basis of a number, and a practical user can get value quickly.
