## Fixes Applied In This Pass

The following changes were made because they were high-confidence P1 trust/copy issues:

- First-minute copy now says nothing affects the user's money view until review.
- Import Review now uses "money view" and "save after review" language instead of "financial reality" language.
- Import Review hides technical parser wording behind "statement reader", "source looked readable", "read wrong" and "source and review details".
- Data Control now says "Accepted money rows" and "source history" instead of "Accepted reality" and "provenance".
- Dogfood status labels now describe local records on this device instead of canonical repository internals.
- Source-level tests now guard against the retired visible copy.
- Static evidence pages were regenerated and after-fix screenshots were captured.

## Update 2026-06-30 (evening) — faithful-port surface (`apps/mobile/src/folio/`)

Commits eb6e0a0 / 3783c9c / a3f81c9 (+ 7147884 for `AUDIT.md`). 0 typecheck errors, 306 folio tests green; the visible fixes were verified on-device by screenshot. These resolve trust issues on the live `folio` faithful-port surface that the 2026-06-23 evidence pass either pre-dated or did not catch (a token-contrast or copy scan cannot catch a *missing* colour or a *hardcoded* sample chart — only looking can). Nothing in the 2026-06-23 scores above is rescored; the corrections below state what is now true on this surface.

State corrections (where an earlier description of app behaviour no longer holds):

- **Fabricated/sample data is no longer present 24/7. RESOLVED (`eb6e0a0`/`3783c9c`).** The trust pattern is now: a cleared/real app shows ONLY the user's own data; demo/illustrative data is gated behind the demo regime (`currentBalance.source === 'sample'`). Concretely on this surface: the Today money-path chart was hardcoded SVG geometry ("salary rise +£2,180 / bill drop −£875 / 7 Jul") and is now plotted from the real `route.points` daily series; the Today summary trio ("Coming in £2,180 / Going out £1,095") and the low-point week tile now read real route totals (`RouteResult.incomingTotal` / `outgoingTotal` / tight point); the Calendar agenda's hardcoded "Check Klarna · 2 of 3" review, the generic UK tax deadlines, and `RECURRING_BILLS` (Octopus/Council Tax/Rent/BT) are now gated behind the demo regime; the Reader screens (Visualizer/Review/Paste/Image), `SubCaughtSheet`, the edit sheets, and `RouteDetailSheet` no longer fall back to sample rows / a fake "Tesco · £42 · 26 Jun" on a cold open — they show honest empty doorways / blank forms; the chart's "breathing room · £100" caption is now just "breathing room". This directly strengthens the local-first / source-clarity / emotional-safety properties this register scores.
- **Melo mood is no longer a no-op. RESOLVED (`eb6e0a0`).** App-wide pressure is now DERIVED from the real route via `derivePressure()`, gated on a real money picture so an empty/cleared app stays neutral calm; the Melo mood picker sets a global override via the new `nav.setPressure`, which propagates to Today / What-if / Melo / chat. (Relevant to UI-TRUST-008's Melo-usefulness concern, though the "explanations sit low on the screen" layout note in UI-TRUST-008 is untouched by this change and remains open.)
- **TimelineScreen dark-mode text is no longer invisible. RESOLVED (`eb6e0a0`).** The TimelineScreen headline + subhead had no colour bound and defaulted to black, rendering invisible on the dark canvas (light mode read fine, which is why the contrast audit missed it). They are now bound to theme `ink`/`muted`.
- **Below-the-fold content on fixed-height surfaces is now reachable. RESOLVED (`eb6e0a0`).** See UI-TRUST-007 above — Privacy/Subscriptions/PaydayRitual/Check-in/Start are wrapped in `ScrollView`; Privacy's "Clear to empty" control, previously unreachable below the fold, now scrolls into view.
- **"Start fresh" no longer reseeds the demo. RESOLVED (`a3f81c9`).** More → "Start fresh" called `resetAll`, which reseeded the demo ("it all came back"); it now calls `resetToEmpty` behind a one-tap confirm. This makes the D3-style guarded start-fresh trustworthy on this surface.
- **Imported transactions keep their real statement date. RESOLVED (`eb6e0a0`).** Import previously stamped rows with "today"; imported transactions now retain their real statement date — a source/trust-clarity correctness fix on the import-review path.
